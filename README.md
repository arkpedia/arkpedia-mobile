# Arkpedia Mobile

Android and iOS shells for **https://www.arkpedia.net**, maintained in the private
`arkpedia/arkpedia-mobile` repository. Both platforms use Capacitor 8.6.0 and the
application identifier `net.arkpedia.mobile`.

The apps load the live website; website releases appear without rebuilding the
shell. An internet connection is required. This repository does not bundle the
Next.js server, game data, or offline content. If loading fails, a small bundled
page offers a retry.

## Download builds

Open [Actions → Mobile builds](https://github.com/arkpedia/arkpedia-mobile/actions/workflows/build.yml),
select a successful run for `main`, and download its artifacts while signed into
GitHub with repository access. They expire after 14 days; **Run workflow** creates
fresh builds.

| Artifact | Contents | Installation |
| --- | --- | --- |
| `arkpedia-android-debug-apk` | `Arkpedia-debug.apk` | Debug-signed Android APK for device testing. |
| `arkpedia-ios-unsigned-ipa` | `Arkpedia-unsigned.ipa` | Device build packaged for later signing. **Cannot be installed until signed and provisioned.** |

Android debug keys are generated on each fresh CI runner. Later builds may require
uninstalling the earlier debug app, which removes that app's local data. Use a
persistent release signing key for upgradeable distributions.

The iOS job deliberately produces an unsigned IPA without Apple credentials. An
unsigned IPA is not an App Store/TestFlight submission or a ready-to-install iPhone
app. For a signed build, follow the Xcode steps below.

## Develop

Use Node 24 LTS, then:

```sh
npm ci
npm run check
npm run sync
```

Commit native project changes under `android/` and `ios/`. The copied web assets and
native Capacitor configuration are generated by `sync` and ignored by Git. Keep
dependency versions and the lockfile together. Rebuild native binaries after
changing dependencies, identifiers, permissions, or native code.

### Android

Requires JDK 21, Android Studio/SDK with Android API 36, and Android SDK licenses
accepted on the development machine. The minimum supported Android version is 7.0
(API 24).

```sh
npm run android:debug
# android/app/build/outputs/apk/debug/app-debug.apk
npm run open:android
```

For a release APK, use Android Studio's **Build → Generate Signed App Bundle / APK**
and a persistent keystore. Keep that keystore and its passwords outside Git. Increase
`versionCode` and `versionName` in `android/app/build.gradle` for releases.

### iOS and signed IPA export

Requires macOS, Xcode 26 or newer, and an Apple signing setup appropriate to the
distribution method. Minimum iOS version: 15.0. Swift packages resolve through Xcode;
CocoaPods is not required.

```sh
npm run sync:ios
npm run open:ios
```

1. In Xcode, select the **App** target, then **Signing & Capabilities**. Select your
   Apple team and enable automatic signing for `net.arkpedia.mobile`. There is no
   widget extension to sign.
2. Increase Version/Build as needed. Select a generic iOS device destination and
   choose **Product → Archive**.
3. In Organizer, choose **Distribute App** and the appropriate method. Export the
   signed `.ipa` for registered devices or upload through the App Store Connect
   workflow. Available methods depend on your Apple account and provisioning.

Never commit certificates, provisioning profiles, keystores, passwords, or API keys.
If signing is automated later, store credentials in GitHub Actions secrets.

## First-version limits and device acceptance

This is a web-wrapper prototype, not an offline/native rewrite. Capacitor documents
`server.url` as a live-reload facility rather than its standard production deployment
model; this project intentionally uses it for the requested live-site wrapper. The
site's origin can interact with Capacitor's built-in bridge, so keep that origin
trusted, do not broaden `allowNavigation`, and review any future native plugin.
The app includes a first-party `ArkpediaAudio` bridge. See [native playback](docs/native-audio.md)
for its origin restriction, synchronization contract and remaining device checks.

Google/Discord sign-in uses the system authentication browser, then a one-time,
proof-protected handoff imports the session into the WebView. See
[account sign-in](docs/native-auth.md). This uses the fixed `net.arkpedia.mobile`
callback scheme, not associated-domain entitlements, and supports Sideloadly signing.
Install `Arkpedia-unsigned.ipa` through Sideloadly; the file itself is unsigned.
Keep the same signing identity/bundle identifier when updating to retain app data.
Real-device OAuth, native background music, file import/export,
downloads, and pop-up behavior also need device verification. Store approval is not
established by a successful build; the current app retains the template launcher
and splash artwork pending branded assets.

Before distributing beyond development testing, verify on Android and iPhone:

- Browse operators, open details, and navigate back (Android Back / iOS edge swipe).
- Launch without connectivity, then reconnect and use **Try again**.
- Check light/dark themes, safe areas, keyboard, landscape, and large text.
- Exercise account sign-in and saves, planner import/export, external links, and music.
- Replace template artwork and review the intended distribution/signing method.

CI proves the native projects compile and runs Android lint. It does not claim that
these device journeys or app-store acceptance have passed.
